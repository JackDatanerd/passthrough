BUGS
B1 (medium) lib/text.js firstNameOf/publicFirstName: the first space-separated token of the resume name became the
   public "first name", so "Dr. Priya Patel" / "Eng. John Kamau" / "CPA Jane Doe" / "Doe, Jane" printed "Dr." / "Eng." /
   "CPA" / "Doe," under "Passthrough Verified" and in the link-preview title. Now: leading titles and credentials are
   skipped ("Eng Hock", "Hon Gil-dong", "Er Wei", "Md Rahman" are real names and stay names unless written as an
   abbreviation with a dot); "Last, First" yields First; an ALL-CAPS name of 3+ letters is title-cased (initials such
   as "J.R." are left alone); a stored value that is only a title ("Dr.", "Doe,") is hidden when the page is read, which
   covers pages issued before this fix. Reaches scan.controller.js through candidateFirstNameFrom (7 call sites).
B2 (low-medium) scan.controller.js nextHashHistory kept only the last 20 superseded fingerprints, and every owner edit
   adds one, so after ~20 edits the FIRST file the candidate emailed fell off and a reader holding it read "not an exact
   copy of anything Passthrough issued" (page) / "no match" (/check). Cap is now constants.MAX_HASH_HISTORY = 200; the
   history read is also null-entry safe.
B3 (trivial) NOT CHANGED: the link-preview Function holds a page's name for up to 60s per data center and social
   platforms hold an unfurl far longer; neither can be purged from the Worker. "Hide my name" still takes effect on the
   page, the API and the next un-cached preview immediately.
