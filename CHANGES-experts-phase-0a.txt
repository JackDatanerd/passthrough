WHAT WAS BUILT
 A1 A "Human rewrite" button on the offer card (FixBanner), as a small secondary block under the AI Fix and "Fix only" lines. It never replaces the AI Fix. Renders nothing unless the flag is on.
 A2 A modal: honest copy (opening soon, not available yet, joining is free, no payment is taken, prices are the expected launch price), the ladder (Human polish; Human rewrite 7-day / 48-hour / 24-hour), a cover letter add-on, the one-sentence privacy line. No preselected tier, no "most popular", no countdown, no scarcity, no live claim.
 A3 Three price variants from product spec 16.1 (USD): low $49/$79/$99/$129 +$25; base $59/$89/$119/$149 +$29; high $69/$99/$139/$179 +$39. The server derives the variant from a random visitor id kept in the browser, so a browser sees the same prices every visit. The browser never sends a variant or a price.
 A4 Events (table human_demand_events): button_shown, button_clicked, tier_selected, cover_letter_toggled, modal_dismissed from the browser; waitlist_submitted written by the server only when a NEW waitlist row is created. Columns: event, visitor id, price variant, tier, cover letter yes/no, time. Unknown keys are rejected, so no resume text, scan contents or contact detail can be stored.
 A5 Waitlist (table human_demand_waitlist): one row per person and tier. Signed in = user id only (account email not copied). No account = email, lower-cased, with the email box ticked. Also: cover letter interest, price variant, quoted prices, contact consent, visitor id. Re-joining the same tier is idempotent (ON CONFLICT DO NOTHING; only cover letter interest and consent are refreshed).
 A6 Routes (all 404 unless HUMAN_DEMAND_ENABLED=true): GET /api/human-demand/config, POST /api/human-demand/events, POST /api/human-demand/waitlist. Per-IP limits: 60/10 min, 120/hour, 10/hour. Input validated with zod (strict).
 A7 Flag: Worker variable HUMAN_DEMAND_ENABLED, on only for the exact string "true". Default off.
 A8 Results: docs/experts/phase-0a-results.sql (7 read-only queries: funnel, tier mix, cover letter attach, toggles, dismissals, two sanity checks). No admin UI, no CSV route.
 A9 Migration 0119: two create table, indexes, row level security on with no policy, revoke all from anon/authenticated, ledger row, schema_version upsert. No function added (nothing to revoke execute on). Nothing existing is altered or dropped (the migration test proves it).
