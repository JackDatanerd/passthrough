Shared frontend (section 11) round 16
- G1 (feature gap): new hooks/useDebouncedState.js - the shared way to debounce a search box (value / committed / commitNow, onCommit runs in the same tick as the commit so "back to page 1" is one request). AdminUsers search used to send a request per keystroke against the 100 / 15 min general limiter (which covers /admin/*); it now waits 350 ms after typing stops, Enter searches at once, and a new search returns to page 1 in the same request. AdminLeads and AdminPartnersLookup keep their own existing debounces (URL-synced / atomic offset reset) - both already correct.
- G2 (gap): hooks/useFetch.js removed (no caller anywhere in the app; only its own test used it). Data loading stays on useApi / useLatestRequest. DELETE these two files with git rm: frontend/src/hooks/useFetch.js, frontend/tests/useFetch.test.jsx.
- B1 (bug): Menu focused its first item with a plain focus() before the layout effect moved the list to its fixed position; near the bottom of the viewport the browser scrolled to reveal it and Menu's own scroll listener closed the menu immediately. Now focus({ preventScroll: true }).
- B2 (bug, confirmed by test): lib/api.js - a request still in flight under the OLD token that failed 401 after the person signed in again in place (SessionResumePrompt) was classified 'stale' and surfaced a raw auth error although the session was valid. Sessions resumed in place are remembered (by session id) and such stragglers are replayed once under the new token. Never replayed across accounts; at most once; cleared when a session ends.
- Test fix (outside section, stale test): pages/AuthForms.round3.test.jsx expected two identical "Show password" buttons; round 15 deliberately named the second "Show password: Confirm password". The test failed on the untouched repo and now asserts the real names.
